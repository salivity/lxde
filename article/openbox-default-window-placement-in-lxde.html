Openbox Default Window Placement in LXDE

This article explains how the Openbox window manager positions newly opened application windows by default within an LXDE session. It covers the underlying placement policy, the conditions that dictate window positioning on the screen, and where this behavior is defined in the system configuration files.

By default, Openbox utilizes a policy known as Smart Placement. Under this algorithm, Openbox automatically positions new application windows in the largest available empty space on the active desktop, actively seeking to prevent windows from overlapping existing ones.

When a new application launches, the window placement follows a specific hierarchy based on screen availability:

  1. Unoccupied Screen Space: Openbox scans the current workspace to locate free, unmapped screen coordinates. If sufficient space exists, the new window is aligned within that vacant area.
  2. Empty Desktop: If no other windows are currently open, Openbox places the application window in the center of the active monitor.
  3. Crowded or Full Desktop: If the screen already contains overlapping windows or lacks a large enough gap to fit the new window, Openbox falls back to centering the window on the display or placing it with minimal overlap over existing windows.

This behavior is controlled via the Openbox configuration file. Within an LXDE environment, these settings are typically loaded from ~/.config/openbox/lxde-rc.xml (user level) or /etc/xdg/openbox/LXDE/rc.xml (system level). The behavior is defined within the <placement> block:

<placement>
  <policy>Smart</policy>
  <center>yes</center>
  <monitor>Active</monitor>
</placement>

With <policy>Smart</policy> and <center>yes</center> active, Openbox guarantees that windows default to open spaces first and prioritize the center of the active monitor whenever smart positioning is not feasible.
