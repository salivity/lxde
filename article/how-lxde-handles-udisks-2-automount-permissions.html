How LXDE Handles Udisks2 Automount Permissions

This article explains how the Lightweight X11 Desktop Environment (LXDE) manages permissions for automatically mounting storage devices using udisks2. It identifies the underlying authorization engine responsible for permission evaluation, outlines the roles played by PCManFM and session daemons, and details how these components interact to allow desktop users to access removable media without requiring administrative privileges.

The Core Permission Engine: Polkit

The engine that manages auto-mounting permissions for udisks2 inside an LXDE session is Polkit (formerly known as PolicyKit).

While udisks2 provides the D-Bus interface and performs the low-level operations of probing, partitioning, and mounting block devices, it does not define or enforce its own access policies. Instead, whenever a request to mount a drive is initiated, udisks2 queries Polkit to verify whether the requesting user account has the required privileges.

Polkit regulates these operations through predefined policy rules. For udisks2, key actions include:

  • org.freedesktop.udisks2.filesystem-mount: Authorizes the mounting of a filesystem.
  • org.freedesktop.udisks2.filesystem-mount-system: Authorizes mounting devices considered internal or system-level.
  • org.freedesktop.udisks2.filesystem-mount-other-seat: Authorizes actions initiated outside the primary local seat.

The Role of PCManFM and libfm

While Polkit enforces permissions, the component requesting the auto-mount inside an LXDE session is PCManFM (via libfm).

PCManFM runs in the background as a desktop manager and volume monitor. When a removable drive (such as a USB flash drive) is plugged into the system, the Linux kernel informs udev, which in turn alerts the udisks2 daemon. PCManFM detects this event over the system D-Bus and automatically triggers a mount call to udisks2.

Session Tracking and Authentication Agents

For Polkit to grant permission to an LXDE user without prompting for a root password, two additional components must be active:

  1. Session Tracker (systemd-logind or elogind): Polkit policies typically grant mounting privileges automatically only if the user is in an "active" and "local" session. The session manager registers the graphical LXDE login and informs Polkit that the user is physically present at the console.
  2. Polkit Authentication Agent (lxpolkit): If an action requires elevated authentication—such as mounting an internal drive—Polkit delegates the password prompt to a graphical agent. LXDE includes lxpolkit as part of its core session (lxsession) to display the desktop dialog requesting authorization.

When an LXDE session is properly configured, systemd-logind validates the session state, PCManFM initiates the mount request, and Polkit authorizes udisks2 to mount the drive directly to /media/$USER/ without administrative intervention.
