Set cgroup Resource Limits for an LXDE Session

This article explains how to configure control group (cgroup) resource limits for an entire LXDE desktop session. It covers the primary configuration methods using systemd—the modern cgroup manager on Linux—to enforce CPU, memory, and I/O constraints across all processes spawned within the user's graphical session, as well as the legacy PAM configuration alternative.

Method 1: The Systemd User Slice (Recommended)

Modern Linux distributions manage cgroups via systemd. When a user logs into LXDE via a display manager (such as LightDM) or standard login, systemd-logind automatically places the user's session into a designated slice named user-<UID>.slice.

To apply limits to the entire session for all users, create a drop-in configuration file for the user slice:

sudo mkdir -p /etc/systemd/system/user-.slice.d/
sudo nano /etc/systemd/system/user-.slice.d/limits.conf

To limit only a specific user account (for example, UID 1000):

sudo mkdir -p /etc/systemd/system/user-1000.slice.d/
sudo nano /etc/systemd/system/user-1000.slice.d/limits.conf

Add your cgroup resource limit directives in the [Slice] section:

[Slice]
# Limit total RAM usage for the session
MemoryMax=4G

# Limit CPU consumption (e.g., 200% equals 2 full CPU cores)
CPUQuota=200%

# Set CPU scheduling weight (default is 100)
CPUWeight=50

# Limit maximum number of processes/threads
TasksMax=2048

Reload the systemd daemon to activate the configuration:

sudo systemctl daemon-reload

Method 2: Wrapping the LXDE Session Startup

If you want to apply cgroup limits specifically to LXDE rather than the user's entire account, you can launch the session inside a custom systemd scope.

  1. Open the LXDE desktop session definition file: /usr/share/xsessions/LXDE.desktop

  2. Locate the execution line:

    Exec=/usr/bin/startlxde

  3. Modify it to execute under systemd-run:

    Exec=systemd-run --user --scope --slice=lxde.slice /usr/bin/startlxde

  4. Create the corresponding slice configuration at ~/.config/systemd/user/lxde.slice:

    [Slice]
MemoryMax=3G
CPUQuota=150%

  5. Reload the user systemd instance:

    systemctl --user daemon-reload

Method 3: Legacy Control via libcgroup and PAM

On systems not running systemd (such as distributions using SysVinit or OpenRC), resource limits are managed through pam_cgroup and /etc/cgconfig.conf.

  1. Define the cgroup in /etc/cgconfig.conf:

    group lxde_users {
    memory {
        memory.limit_in_bytes = 4294967296; # 4 GB
    }
    cpu {
        cpu.shares = 512;
    }
}

  2. Assign users or the session binary in /etc/cgrules.conf:

    # <user>:<process>   <controllers>   <cgroup>
*:lxsession          memory,cpu      lxde_users/

  3. Ensure /etc/pam.d/common-session or /etc/pam.d/lightdm includes the cgroup module:

    session optional pam_cgroup.so

Verifying Active Limits

After logging into the LXDE session, verify that the limits are active:

  • View the control group hierarchy and processes:

    systemd-cgls

  • Monitor real-time resource utilization by cgroup:

    systemd-cgtop
