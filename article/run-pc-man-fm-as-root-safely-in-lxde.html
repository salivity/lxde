Run PCManFM as Root Safely in LXDE

Managing system files with root privileges inside a graphical file manager can lead to permission corruption, configuration overwrites, and security vulnerabilities if done incorrectly. This guide explains how to properly configure and execute root instances of PCManFM within the LXDE desktop environment. By using PolicyKit (pkexec) and isolated environment configurations rather than direct sudo commands, you ensure that user-space configurations remain untouched and file ownership integrity is preserved.

The Risks of Standard sudo pcmanfm

Running sudo pcmanfm directly from a terminal or custom launcher is dangerous. When a graphical GTK application runs directly under standard sudo, it frequently writes configuration caches, socket files, and history records into your standard user home directory (/home/username/.config) with root ownership. This locks regular user processes out of their own settings, causing desktop crashes or theme breakage. Furthermore, sharing the active X11 display session directly with root grants elevated permissions to any rogue script or library hooked into that session.

Method 1: Using PolicyKit (pkexec)

The standard and most secure method to elevate privileges for a desktop utility is via PolicyKit. PolicyKit drops unneeded privileges, prompts for administrative credentials securely, and does not carry over the regular user's environment wholesale.

To launch PCManFM via PolicyKit, open your terminal and run:

pkexec pcmanfm

If your distribution requires explicit PolicyKit action rules for graphical applications, create an action definition file at /usr/share/polkit-1/actions/org.lxde.pcmanfm.policy:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE policyconfig PUBLIC
 "-//freedesktop//DTD PolicyKit Policy Configuration 1.0//EN"
 "http://www.freedesktop.org/standards/PolicyKit/1/policyconfig.dtd">
<policyconfig>
  <vendor>LXDE</vendor>
  <vendor_url>https://lxde.org</vendor_url>
  <action id="org.lxde.pcmanfm">
    <description>Run PCManFM with elevated privileges</description>
    <message>Authentication is required to run PCManFM as root</message>
    <defaults>
      <allow_any>auth_admin</allow_any>
      <allow_inactive>auth_admin</allow_inactive>
      <allow_active>auth_admin</allow_active>
    </defaults>
    <annotate key="org.freedesktop.policykit.exec.path">/usr/bin/pcmanfm</annotate>
    <annotate key="org.freedesktop.policykit.exec.allow_gui">true</annotate>
  </action>
</policyconfig>

Method 2: Isolating the Root Profile Configuration

To prevent root instances from touching user-level bookmarks, cache, or thumbnail databases, explicitly instruct PCManFM to use root's dedicated configuration directory:

pkexec env XDG_CONFIG_HOME=/root/.config XDG_DATA_HOME=/root/.local/share pcmanfm

This ensures that root configurations are segregated in /root/, preventing any contamination of the local user's home permissions.

Creating a Safe Application Launcher

To add an "Open as Root" launcher directly to the LXDE application menu:

  1. Create a desktop entry file at /usr/share/applications/pcmanfm-root.desktop.
  2. Add the following contents:
[Desktop Entry]
Type=Application
Name=File Manager (Root)
Comment=Browse the filesystem with administrative privileges
Exec=pkexec env XDG_CONFIG_HOME=/root/.config XDG_DATA_HOME=/root/.local/share pcmanfm
Icon=system-file-manager
Terminal=false
Categories=System;FileTools;
  1. Save the file and reload the LXDE menu. The entry will prompt for the administrative password via the graphical polkit-agent and open safely in an isolated session.

Alternative: Using the GVFS Admin Backend

If installed on your distribution (gvfs-backends), the safest way to edit system files is without running the full file manager GUI as root. You can open your standard PCManFM instance and navigate to:

admin:///

This uses GVFS to communicate with a root-privileged backend daemon for file reading and writing while keeping the entire interface process constrained to regular user permissions.
