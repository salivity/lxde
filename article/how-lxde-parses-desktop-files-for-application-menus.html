How LXDE Parses Desktop Files for Application Menus

LXDE populates its application launcher by adhering to standard freedesktop.org specifications through a dedicated caching daemon and menu layout definitions. Rather than reading .desktop files directly in real-time, LXDE coordinates between the panel plugin, an XML-based menu hierarchy, and a background service called menu-cache to monitor, parse, and render applications into organized categories efficiently.

The XDG Standards Foundation

LXDE (Lightweight X11 Desktop Environment) relies on two primary specifications defined by freedesktop.org:

  1. The Desktop Entry Specification: Governs the syntax and key-value pairs inside .desktop files.
  2. The Desktop Menu Specification: Defines how desktop entries are merged, filtered, and structured into an XML hierarchy using .menu files.

Key File Locations

To find applications, LXDE inspects standard XDG directory paths:

  • System-wide applications: /usr/share/applications/ and /usr/local/share/applications/
  • User-specific applications: ~/.local/share/applications/
  • Menu layouts: /etc/xdg/menus/lxde-applications.menu (or the user override in ~/.config/menus/)

If an application entry exists in both user and system directories with the same filename, the user-level file overrides the system-level file.

The Parsing Pipeline: menu-cache and lxpanel

To keep memory usage minimal and menu response instant, LXDE offloads the heavy lifting from the main panel (lxpanel) to a helper library and daemon called menu-cache (menu-cached).

  1. Reading the Layout Definition: The process begins when lxpanel requests the menu tree. The menu-cache service reads lxde-applications.menu. This XML file outlines the top-level categories (such as Accessories, Internet, and System) and sets matching rules based on XDG categories.

  2. Parsing Individual .desktop Files: The menu-cache daemon scans the application directories and parses each .desktop file line by line, evaluating standard keys:

    • Name / GenericName: Extracted to display the human-readable label in the menu.
    • Exec: Read to define the command invoked when clicked.
    • Icon: Evaluated against the active icon theme to render the application's graphic.
    • Categories: Semicolon-separated values (e.g., Network;WebBrowser;) mapped against the criteria declared in the .menu XML layout.
    • NoDisplay=true: Instructs the parser to ignore the file entirely.
    • OnlyShowIn / NotShowIn: Checks if the desktop entry is restricted to specific desktop environments (e.g., GNOME, KDE) or excluded from LXDE.
    • Hidden=true: Marks the entry as deleted or disabled.

  3. Building the In-Memory Cache: Instead of forcing the panel to parse hundreds of plain-text .desktop files every time the menu opens, menu-cached organizes the valid entries into a binary cache format.

  4. Delivering to lxpanel: lxpanel connects to menu-cached via a UNIX domain socket. The panel receives the pre-built, sorted menu structure and renders the graphical GTK menu tree.

Dynamic Updates via inotify

LXDE dynamically updates its application menu without requiring a panel restart. The menu-cached daemon uses the Linux kernel's inotify subsystem to watch target directories (/usr/share/applications/, etc.).

When a package manager installs, modifies, or removes a .desktop file:

  • An inotify event signals menu-cached.
  • The daemon re-parses the affected files and regenerates the binary cache.
  • An IPC notification is dispatched to lxpanel, prompting the menu widget to reload its entries automatically.
