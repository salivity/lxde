Where to Find LXDE Desktop Crash Reports

When LXDE desktop components like PCManFM, LXPanel, or the Openbox window manager fail, crash information is recorded across several standard Linux log files rather than a single dedicated LXDE directory. Depending on your distribution, crashes are primarily written to the user session log (~/.xsession-errors), captured by the systemd journal and core dump services, or saved in system-wide crash dump directories like /var/crash. Inspecting these locations allows you to view stack traces, fatal errors, and diagnostic output to identify the root cause of desktop instability.

The User Session Log: ~/.xsession-errors

The primary place to look for application crashes occurring within an active LXDE session is the .xsession-errors file in your user home directory:

~/.xsession-errors

Because LXDE components output directly to standard error (stderr), unhandled exceptions, segfault notices, and component termination warnings generated by lxpanel, pcmanfm, and openbox are piped straight to this file. Note that this file is overwritten each time you log in, so it must be inspected immediately after a crash or preserved by copying it to another location.

Systemd Journal and Core Dumps

On modern Linux distributions that utilize systemd, unexpected terminations of desktop processes are captured automatically by systemd-journald and systemd-coredump.

  • View Recent Desktop Errors:
    Run journalctl --user -xe to view recent session-level messages, or use journalctl -b to view all logs from the current boot.

  • Locate Core Dumps:
    If a component crashes due to a segmentation fault, systemd records the core dump. You can list recorded crashes by running:

    coredumpctl list

    To view the stack trace and detailed diagnostic report for a specific crash (such as lxpanel), run:

    coredumpctl info lxpanel

Distribution-Specific Crash Directories

Many distributions bundle background reporting daemons that automatically generate full crash reports containing stack traces, package versions, and memory dumps:

  • Debian and Ubuntu (Apport): Crash reports are stored in /var/crash/. Files ending in .crash correspond to specific failed executables (for example, _usr_bin_lxpanel.1000.crash).
  • Fedora and RHEL (ABRT): The Automated Bug Reporting Tool saves crash data in /var/spool/abrt/.

Display Manager and X Server Logs

If an LXDE component crash causes the entire graphic session to reset to the login screen, the issue may stem from the display server or display manager:

  • LightDM Logs: If using LightDM (the standard display manager for LXDE), check /var/log/lightdm/lightdm.log and /var/log/lightdm/x-0.log.
  • Xorg Log: General display server errors are stored in /var/log/Xorg.0.log or inside the user directory at ~/.local/share/xorg/Xorg.0.log.
