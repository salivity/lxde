How LXDE Handles Multiple Display Managers

When multiple display managers are installed alongside the Lightweight X11 Desktop Environment (LXDE), conflict resolution is handled entirely by the underlying operating system and init system rather than LXDE itself. Because LXDE is a desktop session that executes after authentication, it relies on system-level configuration files, package managers, and service controllers to determine which display manager launches on boot.

The Role of LXDE Versus Display Managers

LXDE functions strictly at the desktop session tier. A display manager (such as LXDM, LightDM, or GDM) runs at the system startup tier to initiate the X server and provide a graphical login prompt. LXDE registers its session via a .desktop entry located in /usr/share/xsessions/lxde.desktop. Any active display manager reads this directory to present LXDE as an available session option, but LXDE possesses no internal mechanism to select, start, or prioritize one display manager over another.

Systemd Service Symlinks

On modern Linux distributions utilizing systemd, display manager conflicts are resolved through a dedicated service alias.

  1. Systemd uses the target alias /etc/systemd/system/display-manager.service.
  2. When multiple display managers are installed, this target points via a symbolic link to only one manager's unit file (such as /usr/lib/systemd/system/lxdm.service or /usr/lib/systemd/system/lightdm.service).
  3. If two services attempt to start simultaneously, systemd prevents duplicate X server instances by allowing only the enabled service symlink to activate at default graphical targets.

To select a specific manager manually under systemd:

sudo systemctl disable lightdm
sudo systemctl enable lxdm --force

Distribution-Specific Alternative Systems

On Debian, Ubuntu, and related distributions, display manager conflicts are governed by the update-alternatives mechanism and the debconf database.

  • Configuration File: The active display manager path is stored directly inside /etc/X11/default-display-manager.
  • Conflict Arbitration: Installing a new display manager prompts debconf to present a selection menu asking the administrator to select the default.
  • Manual Reconfiguration: If conflicts arise or the wrong manager starts, the choice can be adjusted using:
sudo dpkg-reconfigure lxdm

Or by updating the generic alternatives pointer:

sudo update-alternatives --config x-display-manager

Fallback Behavior in SysVinit

On legacy or lightweight distributions without systemd, display managers are started via SysVinit runlevel scripts in /etc/init.d/. In these environments, scripts check /etc/X11/default-display-manager sequentially. The first script matching the declared path initiates the X server, while preceding and following initialization scripts detect that a graphical session or lock file is already active and exit gracefully without launching a second interface.
