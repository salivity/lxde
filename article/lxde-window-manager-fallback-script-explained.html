LXDE Window Manager Fallback Script Explained

This article provides an overview of how the Lightweight X11 Desktop Environment (LXDE) handles window manager failures, identifying the primary initialization script—startlxde—and explaining how it coordinates with the session manager to execute fallback behavior if Openbox fails to start.

In an LXDE environment, the shell script that defines and initializes the desktop session is /usr/bin/startlxde. When a user logs in, this script sets up essential environment variables (such as XDG_CONFIG_DIRS and XDG_DATA_DIRS) and launches the core session manager, lxsession.

While startlxde initiates the desktop, it passes the responsibility of executing and monitoring the window manager to lxsession. By default, lxsession attempts to load Openbox using the wrapper command openbox-lxde. This default preference is stored in the session configuration file located at /etc/xdg/lxsession/LXDE/desktop.conf (or the user equivalent in ~/.config/lxsession/LXDE/desktop.conf) under the window_manager= key.

If Openbox crashes or fails to launch during initialization, the fallback behavior is governed at two levels:

  1. lxsession Fallback Handling: If the configured window manager specified in desktop.conf fails to run, lxsession attempts to detect and launch an alternative, available window manager present on the system to prevent an unresponsive desktop.
  2. System-Level Fallback (x-window-manager): On many Debian- and Ubuntu-based Linux distributions, startlxde and the underlying X session rely on the /usr/bin/x-window-manager alternative system. If the designated openbox-lxde binary cannot be found or executed, the desktop delegates execution to the system's registered fallback alternative (such as Compiz, Metacity, or Xfwm4).

To manually redefine or override this fallback behavior, administrators can edit the /usr/bin/startlxde script directly to introduce conditional checks, or modify desktop.conf to declare a backup window manager before the session initializes.
