How to Fix Screen Tearing in LXDE Video Playback

Screen tearing during video playback in LXDE is a common issue primarily caused by the desktop’s lack of a built-in compositing manager to enforce vertical synchronization (VSync). This article explains the technical reasons behind this visual artifact and provides clear, actionable steps to eliminate it through standalone compositors, graphics driver configurations, and media player optimizations.

What Causes Screen Tearing in LXDE

LXDE is designed to be extremely lightweight and fast. To achieve this, it relies on Openbox as its default window manager. Openbox is a non-compositing window manager, meaning it does not manage a shared off-screen buffer before drawing windows to the display.

Without compositing or active VSync, the graphics card pushes new frames to the display buffer while the monitor is in the middle of a refresh cycle. As a result, the monitor displays parts of two different frames at the same time, producing a visible horizontal split line known as screen tearing. This effect is especially noticeable during fast-paced video playback or rapid camera pans.

Solution 1: Install and Configure Picom

The most reliable fix for LXDE is to install a lightweight standalone compositor, such as Picom (a maintained fork of Compton). Picom introduces double-buffering and VSync without consuming significant system resources.

1. Install Picom

Install Picom using your distribution's package manager:

  • Debian/Ubuntu/Raspberry Pi OS:

    sudo apt install picom

  • Arch Linux:

    sudo pacman -S picom

  • Fedora:

    sudo dnf install picom

2. Configure Picom for VSync

Create a configuration file at ~/.config/picom/picom.conf:

backend = "glx";
vsync = true;
use-damage = true;

If your graphics hardware struggles with the OpenGL (glx) backend, change backend = "glx"; to backend = "xrender";.

3. Autostart Picom with LXDE

To make Picom launch automatically upon login:

  1. Open the LXDE autostart file:

    nano ~/.config/lxsession/LXDE/autostart

    (On some distributions, such as Raspberry Pi OS, use ~/.config/lxsession/LXDE-pi/autostart or /etc/xdg/lxsession/LXDE/autostart).

  2. Add the following line to the end of the file:

    @picom -b

  3. Save the file and restart your session.

Solution 2: Enable TearFree in the Graphics Driver (Intel and AMD)

If you use Intel or AMD graphics, you can force VSync at the X11 server level using the TearFree option. This often resolves tearing completely without needing a compositor.

For Intel Graphics

Create the file /etc/X11/xorg.conf.d/20-intel.conf:

Section "Device"
    Identifier  "Intel Graphics"
    Driver      "intel"
    Option      "TearFree"    "true"
EndSection

For AMD Graphics

Create the file /etc/X11/xorg.conf.d/20-amdgpu.conf:

Section "Device"
    Identifier  "AMD Graphics"
    Driver      "amdgpu"
    Option      "TearFree"    "true"
EndSection

Restart your computer or display manager to apply the changes.

Solution 3: Enable Full Composition Pipeline (NVIDIA)

Users with proprietary NVIDIA drivers can eliminate tearing using the driver's built-in composition options.

  1. Open the NVIDIA X Server Settings tool.
  2. Navigate to X Server Display Configuration.
  3. Click Advanced.
  4. Check the box for Force Full Composition Pipeline.
  5. Click Apply, then Save to X Configuration File.

Alternatively, run this command in a terminal to apply it dynamically:

nvidia-settings --assign CurrentMetaMode="nvidia-auto-select +0+0 { ForceFullCompositionPipeline = On }"

Solution 4: Adjust Media Player Video Output

If tearing only occurs within a specific media player, the player may be using an unoptimized video rendering sink.

  • VLC Media Player: Go to Tools > Preferences > Video. Under the Display section, change Output from "Automatic" to OpenGL video output or X11 video output (XCB).
  • MPV: Add vo=gpu and gpu-context=x11egl to your ~/.config/mpv/mpv.conf file to leverage modern hardware rendering with synchronization.
