Contribute Translations to LXDE Components

Contributing new translations to the Lightweight X11 Desktop Environment (LXDE) allows the desktop interface to reach users worldwide in their native languages. This guide outlines the complete process of contributing translations to LXDE components, from using web-based translation platforms to manually editing localization files via Git repositories.

Using the Web-Based Platform (Transifex)

The primary and most accessible method for translating LXDE components is through Transifex, an online localization platform.

  1. Create an Account: Register on Transifex.
  2. Join the LXDE Project: Search for the official LXDE project hub and request to join the translation team for your specific language. If your language is not listed, submit a request to the project coordinators to add it.
  3. Select a Component: Choose the LXDE component you want to translate, such as pcmanfm, lxpanel, or lxsession.
  4. Translate Strings: Use the web editor to translate untranslated strings, review existing ones, and save your work. Project maintainers periodically pull completed translations from Transifex directly into the upstream source code.

Manual Contribution via Git and GNU gettext

Developers who prefer working locally with version control can edit and submit translation files directly using standard GNU gettext tools.

1. Obtain the Source Code

Clone the repository of the desired LXDE component from the official LXDE GitHub organization:

git clone https://github.com/lxde/<component-name>.git
cd <component-name>

2. Locate the Localization Files

Navigate to the po/ directory inside the repository. This directory contains:

  • The translation template file (<component-name>.pot)
  • Existing language translation files (<language_code>.po)
  • The LINGUAS file, which lists all active languages

3. Create or Update the PO File

  • For a new language: Initialize a new .po file from the template using msginit:

    msginit --input=<component-name>.pot --locale=<language_code> --output=<language_code>.po

    After creating the file, open po/LINGUAS in a text editor and append your language code (e.g., fr, de, pt_BR) to the list in alphabetical order.

  • For an existing language: Update the file against the latest template using msgmerge:

    msgmerge --update <language_code>.po <component-name>.pot

4. Edit Translations

Open the <language_code>.po file using a dedicated translation editor like Poedit, or a standard text editor. Translate each msgid (the original English string) into the corresponding msgstr (the localized string):

msgid "Preferences"
msgstr "Paramètres"

5. Verify and Test

Compile the .po file to ensure there are no syntax errors:

msgfmt -c -v -o /dev/null <language_code>.po

To test the translation in the interface, build and install the component in a test environment, then launch it with your target locale set in the environment variables (e.g., LANG=fr_FR.UTF-8 lxpanel).

Submitting the Changes

Once your changes are complete and verified:

  1. Commit the updated or newly created .po file and the modified po/LINGUAS file.
  2. Push the branch to your personal fork of the repository.
  3. Open a Pull Request on GitHub with a clear title specifying the language added or updated (e.g., "Add Spanish translation for pcmanfm").
