Replace LXSession with Another Session Manager

Yes, LXSession can be replaced with an alternative session manager or a simple startup script while continuing to use individual LXDE components. Because the Lightweight X11 Desktop Environment (LXDE) adheres strictly to the Unix philosophy of modularity, its core utilities do not strictly depend on LXSession to function. This article outlines how session management works in LXDE, alternative session managers you can use, and how to preserve key desktop components like LXPanel and PCManFM under a new manager.

Understanding LXDE Modularity

LXSession is the standard session manager used in LXDE. Its primary responsibilities include:

  • Running the window manager (typically Openbox).
  • Initializing desktop settings via XSettings.
  • Launching a PolicyKit agent (lxpolkit).
  • Executing autostart programs defined in system and user configurations.
  • Running power management utilities.

The visual and functional parts of LXDE—such as pcmanfm (file manager and desktop icon handler) and lxpanel (taskbar and system tray)—are standalone X11 applications. They do not require lxsession to run; they only require an active X server, D-Bus, and a window manager.

Suitable Alternatives to LXSession

Depending on your workflow and system requirements, you can replace LXSession with:

  • Direct Xinit (~/.xinitrc): The simplest method. A standard shell script manages the lifecycle of your session, relying on the window manager to keep the X session alive.
  • Openbox Session (openbox-session): Uses Openbox’s native session launcher, executing background utilities via ~/.config/openbox/autostart.
  • Xfce4 Session (xfce4-session): Provides a robust, standards-compliant session manager with integrated session saving and power control, while still allowing you to swap out default Xfce panels for LXPanel.
  • Systemd User Sessions: Manages graphical components as independent systemd --user services, improving crash recovery and process tracking.

How to Set Up an Alternative Session

To run an LXDE environment without LXSession, configure your chosen manager or startup script to execute the desktop elements manually.

Example: Using .xinitrc or Openbox Autostart

If you start your desktop via startx or use an Openbox-centric session, configure your startup file (such as ~/.xinitrc or ~/.config/openbox/autostart) with the following sequence:

# 1. Start a Polkit authentication agent (critical for root prompts)
lxpolkit &

# 2. Start the LXDE panel
lxpanel &

# 3. Manage desktop icons and wallpaper with PCManFM
pcmanfm --desktop &

# 4. Optional: Notification daemon and power management
dunst &
xfce4-power-manager &

# 5. Start the window manager (omit '&' if in .xinitrc, as it keeps the session open)
exec openbox

Caveats and Missing Features

Replacing LXSession requires manually addressing specific duties it handles automatically:

  1. PolicyKit Agent: LXSession starts lxpolkit automatically. Under a different session manager, ensure an authentication agent (lxpolkit, mate-polkit, or polkit-gnome) starts in the background to handle administrative authorization dialogs.
  2. Session Termination and Logout: The default LXDE logout dialog (lxsession-logout) interacts directly with LXSession to trigger shutdowns, reboots, and logouts. Without LXSession, you will need to map your logout actions to the native commands of your new session manager or use system commands like loginctl or systemctl.
  3. XSettings and Theming: LXSession applies GTK themes and font rendering settings via lxsettings-daemon. When replacing it, ensure your new session manager includes an XSettings daemon (like xsettingsd), or configure your GTK settings explicitly in ~/.config/gtk-3.0/settings.ini and ~/.gtkrc-2.0.
