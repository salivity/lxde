How LXDE Manages System-Wide Environment Variables

The Lightweight X11 Desktop Environment (LXDE) manages system-wide environment variables through a multi-stage startup sequence that combines standard Linux display manager initialization, system shell profiles, X11 session scripts, and its internal session manager, lxsession. Because LXDE is designed to be minimal, it relies heavily on standard POSIX and freedesktop.org conventions rather than maintaining an isolated or proprietary configuration daemon, ensuring that variables declared at the system level propagate down through the window manager and desktop panel to user-launched applications.

1. Display Manager and PAM Initialization

The startup process begins before LXDE itself executes. When a user logs in via a display manager (such as LightDM or LXDM), the Pluggable Authentication Module (PAM) architecture initializes the user session:

  • /etc/environment: Loaded directly by pam_env.so. This file defines global, system-wide key-value pairs (such as system PATH modifications) without requiring shell expansion.
  • /etc/security/pam_env.conf: Read by PAM to set or override fine-grained user and system variables during authentication.

Variables established at this stage become part of the initial process environment that wraps the incoming session.

2. Sourcing System Profiles and Shell Scripts

Once authentication completes, the display manager invokes the session startup script, typically executed as a login shell or through an environment that loads standard login configurations:

  • /etc/profile: The system-wide initialization file for login shells is executed.
  • /etc/profile.d/*.sh: Scripts placed within this directory by system administrators and packages are executed in alphabetical order, exporting critical system-wide variables for toolchains, desktop paths, and runtime libraries.

3. X11 Session Initialization

Before lxsession launches, the X session runner (typically /etc/X11/Xsession on Debian- and Ubuntu-based distributions) executes:

  • /etc/X11/Xsession.d/: Scripts in this directory execute sequentially. They set up desktop-agnostic variables such as XDG_DATA_DIRS, XDG_CONFIG_DIRS, and windowing settings.
  • Any variable exported during the execution of /etc/X11/Xsession.d/ is appended to the environment of the active subshell.

4. LXSession Execution and Configuration Loading

At the conclusion of the X session startup, the system invokes lxsession -s LXDE -e LXDE. As the core session manager, lxsession coordinates the startup of LXDE components:

  • System-Wide Desktop Configuration (/etc/xdg/lxsession/LXDE/desktop.conf): This file defines global session behavior, default window managers, and environment definitions under specific directives.
  • Global Autostart (/etc/xdg/lxsession/LXDE/autostart): While primarily used to start background programs (such as lxpanel and pcmanfm), wrapper commands or scripts can be defined here to manipulate the session environment before primary desktop tools appear.

If a user does not have a local override in ~/.config/lxsession/LXDE/, lxsession falls back entirely on these global configurations.

5. Environment Inheritance Across the Process Tree

LXDE achieves uniform environment variable access through standard UNIX process inheritance:

  1. lxsession inherits all environment variables set by PAM, /etc/profile, and /etc/X11/Xsession.d/.
  2. lxsession spawns the window manager (typically Openbox), the desktop manager (pcmanfm --desktop), and the taskbar (lxpanel).
  3. Whenever a user launches a software program from the application menu or the desktop, the request is handled by lxpanel or pcmanfm.

Because child processes inherit the environment of their parent process, any system-wide variable defined upstream remains accessible to every graphical application launched within the LXDE session.
