Scale Legacy GTK2 Applications in LXDE

Running legacy GTK2 applications within the lightweight LXDE desktop environment often results in tiny, unreadable user interfaces on modern high-resolution (HiDPI) monitors because GTK2 lacks native scaling support. While modern toolkits offer built-in fractional and integer scaling, legacy GTK2 applications require alternative methods to remain usable. This guide outlines the most effective workarounds for scaling GTK2 software in LXDE, including font DPI adjustments, GTK2 theme and icon tweaks, fractional display scaling with xrandr, and containerized window scaling via Xpra.

1. Adjust Font DPI via Xresources and LXAppearance

While GTK2 cannot scale entire interfaces natively, scaling text forces many UI elements, like menus and buttons, to expand proportionally to fit larger fonts.

  1. Open lxappearance and navigate to the Font tab to increase the default font size.

  2. For system-wide DPI scaling, define the DPI value in your ~/.Xresources file:

    Xft.dpi: 192

    (Note: 96 is standard DPI; 192 represents a 200% scale).

  3. Apply the changes immediately in your session by running:

    xrdb -merge ~/.Xresources

2. Force Larger Icons and Widget Padding in ~/.gtkrc-2.0

Text scaling alone may leave checkmarks, scrollbars, and toolbars disproportionately small. You can directly edit the GTK2 configuration file to force larger interface components.

Add the following directives to ~/.gtkrc-2.0:

# Enforce larger standard icon sizes
gtk-icon-sizes = "panel-menu=32,32:gtk-button=32,32:gtk-small-toolbar=32,32:gtk-large-toolbar=48,48:gtk-dnd=64,64:gtk-dialog=96,96"

# Increase scrollbar width for easier accessibility
style "wider-scrollbar" {
    GtkScrollbar::slider-width = 24
}
class "GtkScrollbar" style "wider-scrollbar"

Pairing these entries with a HiDPI-specific icon pack (like Papirus or Tela) ensures icons remain sharp at larger pixel dimensions.

3. Emulate Integer Scaling with xrandr

If theme tweaks leave the application inconsistent, you can scale the entire display server output using xrandr. This approach renders the screen at a lower virtual resolution and scales it up to your native display.

To scale a 4K display down to an effective 1080p workspace (2x scaling):

xrandr --output <DISPLAY_NAME> --scale 0.5x0.5

(Replace <DISPLAY_NAME> with your active output, such as eDP-1 or HDMI-1, found by running xrandr --query).

To revert the display back to its native unscaled state:

xrandr --output <DISPLAY_NAME> --scale 1x1

4. Isolate Individual Apps Using run_scaled

To scale only specific GTK2 applications without altering the rest of your LXDE desktop, use the third-party utility run_scaled. This tool uses an isolated Xpra session to render the target application at a lower resolution and scale the window up to your monitor's native DPI.

  1. Install xpra and xvfb via your distribution’s package manager:

    sudo apt install xpra xvfb

  2. Download and set up run_scaled:

    git clone https://github.com/kaueraal/run_scaled.git
chmod +x run_scaled/run_scaled
sudo cp run_scaled/run_scaled /usr/local/bin/

  3. Launch your GTK2 application with integer or fractional scaling:

    run_scaled --scale=2 gimp

This method eliminates UI disproportion by scaling both fonts and bitmaps together, making legacy software fully functional on dense pixel displays.
