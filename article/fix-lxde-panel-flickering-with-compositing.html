Fix LXDE Panel Flickering with Compositing

When running a standalone compositor such as Picom or Compton alongside LXDE, users frequently experience persistent flickering on the desktop panel (lxpanel). This visual artifact is typically caused by the compositor attempting to apply desktop effects—such as shadows, fading, or improper redraw cycles—to the panel's dock window, or by an incompatible rendering backend. Resolving this issue requires adjusting the compositor configuration file to exclude the panel from specific effects and ensuring the correct rendering backend and synchronization settings are enabled.

1. Exclude LXPanel from Shadows and Fading

The most common trigger for panel flickering is the compositor drawing drop shadows or fade transitions beneath lxpanel every time a panel plugin updates (such as the system clock or taskbar items).

Open your compositor configuration file (typically located at ~/.config/picom/picom.conf or ~/.config/compton.conf):

nano ~/.config/picom/picom.conf

Add lxpanel to the shadow and fade exclusion lists:

# Exclude lxpanel from drop shadows
shadow-exclude = [
    "name = 'panel'",
    "class_g = 'lxpanel'",
    "class_g = 'LXpanel'",
    "window_type = 'dock'"
];

# Exclude lxpanel from fading transitions
fade-exclude = [
    "class_g = 'lxpanel'",
    "class_g = 'LXpanel'",
    "window_type = 'dock'"
];

2. Configure Dock Window Rules

Ensure the compositor treats dock windows (such as panels) properly by defining specific behavior under the wintypes section at the end of the configuration file:

wintypes:
{
    dock = {
        shadow = false;
        fade = false;
        opacity = 1.0;
        clip-shadow-above = true;
    };
};

This prevents the compositor from constantly redrawing transparent buffers over the panel region.

3. Switch Rendering Backend and Enable VSync

If flickering persists during window movement or desktop usage, the default XRender backend may be conflicting with the graphics driver. Switching to the OpenGL (glx) backend and enabling vertical synchronization (VSync) generally resolves this.

Update the following directives in your configuration file:

backend = "glx";
vsync = true;
glx-no-stencil = true;
glx-no-rebind-pixmap = true;
use-damage = true;

Note: If your system uses low-spec hardware without proprietary graphics drivers and you encounter performance degradation with glx, set backend = "xrender"; while keeping the shadow-exclude rules active.

4. Restart the Compositor

After saving the configuration changes, restart the compositor to apply the new settings:

killall picom && picom -b

(Replace picom with compton if you are using an older LXDE installation).
