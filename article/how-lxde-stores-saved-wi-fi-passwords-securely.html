How LXDE Stores Saved Wi-Fi Passwords Securely

The Lightweight X11 Desktop Environment (LXDE) secures saved Wi-Fi passwords by delegating credential management to underlying system services rather than handling security internally. Depending on the distribution and configuration, LXDE relies either on an encrypted credentials manager like GNOME Keyring via the Secret Service API or on strict POSIX file permissions enforced by system-level daemons like NetworkManager or wpa_supplicant.

Delegation to Network Services

LXDE is designed to be extremely lightweight and modular, meaning it does not include an in-house network configuration daemon. Instead, LXDE interfaces with external connection managers—most commonly NetworkManager through the nm-applet tray interface. When you enter a Wi-Fi password (WPA/WPA2/WPA3 Pre-Shared Key) in an LXDE session, the application passes that secret to the active network backend to handle storage and retrieval.

Encrypted Storage via GNOME Keyring

On modern desktop installations using LXDE alongside NetworkManager, Wi-Fi credentials set for user-only access are secured using GNOME Keyring:

  • Secret Service API: NetworkManager communicates with GNOME Keyring through the Freedesktop.org Secret Service D-Bus specification.
  • Encryption at Rest: Passwords stored in GNOME Keyring are encrypted on disk using standard cryptographic ciphers (typically AES-128 or AES-256).
  • Automatic Unlocking: The keyring is protected by the user’s login password. When a user logs into LXDE via a display manager (such as LightDM) equipped with the Pluggable Authentication Module (pam_gnome_keyring), the keyring automatically decrypts in memory for the duration of the active session.

Restricted System-Level Storage

If a Wi-Fi connection is configured as a system-wide connection—available before user login or shared across multiple users—the credentials are stored directly by NetworkManager:

  • Location: Configuration profiles are saved in /etc/NetworkManager/system-connections/ (or in newer versions, /etc/NetworkManager/system-connections/*.nmconnection).
  • POSIX Access Controls: Inside these files, the Wi-Fi key is stored in plain text or as a pre-shared key hash. Security is maintained entirely through Unix file permissions (-rw------- or 0600), owned exclusively by the root user.
  • Privilege Separation: Non-privileged users and unauthorized processes running within the LXDE session cannot read or access this directory without root privileges.

Minimalist Configurations (wpa_supplicant)

In minimal or lightweight distributions that bypass NetworkManager altogether, LXDE often relies directly on wpa_supplicant:

  • Passwords can be hashed using the wpa_passphrase utility, which derives a 256-bit PSK from the plain-text password and SSID, ensuring the original passphrase is never stored.
  • The resulting configuration is stored in /etc/wpa_supplicant/wpa_supplicant.conf, which is likewise protected by strict 0600 root permissions to prevent unauthorized access.
