Using GNOME Keyring or KeePassXC as Secret Service in LXDE

Lightweight desktop environments like LXDE do not include a native credential management daemon, but you can seamlessly integrate either GNOME Keyring or KeePassXC to provide the standard Freedesktop.org Secret Service API. This article explains how both applications function as secret service providers under LXDE, the configuration steps required to enable them, and how to avoid service conflicts so applications like web browsers, Git, and VS Code can securely store and retrieve passwords.

The Role of Secret Service in LXDE

The Freedesktop.org Secret Service specification allows client applications to store and retrieve passwords via D-Bus under the org.freedesktop.secrets interface. Because LXDE aims to remain minimal, it does not ship with an active secret service daemon by default. Without one, applications that require a secure vault will either prompt for a master password repeatedly or fall back to insecure, plaintext storage. Both GNOME Keyring and KeePassXC can claim this D-Bus interface in an LXDE session.

Integrating GNOME Keyring

GNOME Keyring is the traditional, fully automated choice for desktop password management. When properly integrated with your display manager via PAM (Pluggable Authentication Modules), it automatically unlocks your keyring using your login password.

1. Installation

Install the required packages using your distribution's package manager:

# Debian/Ubuntu
sudo apt install gnome-keyring libpam-gnome-keyring

# Arch Linux
sudo pacman -S gnome-keyring

2. PAM Configuration

To enable automatic unlocking at login, ensure your display manager configuration (such as /etc/pam.d/lightdm or /etc/pam.d/lxdm) includes the GNOME Keyring modules:

auth optional pam_gnome_keyring.so
session optional pam_gnome_keyring.so auto_start

3. LXDE Autostart

Initialize the daemon components when LXDE starts by adding the initialization command to your user autostart file located at ~/.config/lxsession/LXDE/autostart:

@gnome-keyring-daemon --start --components=secrets,pkcs11,ssh

Export the required environment variables in your ~/.xprofile or ~/.bashrc:

export SSH_AUTH_SOCK

Integrating KeePassXC

KeePassXC includes a built-in Freedesktop.org Secret Service implementation, allowing your encrypted .kdbx database to act directly as the system credential vault. This provides cross-platform compatibility and greater control over where your credentials are saved.

1. Enable Secret Service in KeePassXC

  1. Launch KeePassXC and navigate to Tools > Settings.
  2. Select the Secret Service Integration tab.
  3. Check Enable Secret Service Integration.

2. Configure Database Exposure

Open the specific database you wish to expose to the system:

  1. Go to Database > Database Settings > Secret Service Integration.
  2. Select the specific group (or root folder) you want to expose to applications making Secret Service requests.

3. Autostart KeePassXC in LXDE

Because KeePassXC must be running and unlocked to answer D-Bus requests, configure it to start minimized with your LXDE session. Add the following entry to ~/.config/lxsession/LXDE/autostart:

@keepassxc --minimized

Resolving D-Bus Interface Conflicts

Only one provider can bind to the org.freedesktop.secrets D-Bus interface at a time. If both GNOME Keyring and KeePassXC are installed, conflicts can occur:

  • To prefer KeePassXC: Disable the secrets component in GNOME Keyring by launching it with --components=pkcs11,ssh, omitting secrets. Alternatively, mask the GNOME Keyring systemd user service if present:

    systemctl --user mask gnome-keyring-daemon.service

  • To prefer GNOME Keyring: Uncheck Enable Secret Service Integration inside KeePassXC's settings.
