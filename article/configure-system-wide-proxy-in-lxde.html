Configure System-Wide Proxy in LXDE

Unlike heavier desktop environments such as GNOME or KDE, the Lightweight X11 Desktop Environment (LXDE) does not feature a dedicated graphical control panel for global network proxy management. To route all network traffic through a proxy server across an LXDE system, configuration must be performed at the OS level using environment variables and application-specific settings. This guide explains how to define system-wide proxy variables, configure package managers, and verify that all graphical and command-line applications adhere to your proxy settings.

Step 1: Set Global Environment Variables

The most effective way to enforce proxy settings system-wide across both GUI applications and terminal shells is by editing the /etc/environment file.

  1. Open a terminal and open /etc/environment in a text editor with administrative privileges:

    sudo nano /etc/environment

  2. Add your proxy definitions to the bottom of the file. Substitute your actual proxy server IP/hostname and port:

    http_proxy="http://proxy.example.com:8080/"
https_proxy="http://proxy.example.com:8080/"
ftp_proxy="http://proxy.example.com:8080/"
no_proxy="localhost,127.0.0.1,localaddress,.localdomain.com"
HTTP_PROXY="http://proxy.example.com:8080/"
HTTPS_PROXY="http://proxy.example.com:8080/"
FTP_PROXY="http://proxy.example.com:8080/"
NO_PROXY="localhost,127.0.0.1,localaddress,.localdomain.com"

    Note: Both uppercase and lowercase variables are defined because different applications look for different cases.

  3. If your proxy server requires authentication, format the string as follows:

    http_proxy="http://username:password@proxy.example.com:8080/"

  4. Save the file (Ctrl + O, then Enter) and exit the editor (Ctrl + X).

Step 2: Configure Shell Profile for User Sessions

To ensure all user sessions and non-login shells launched within LXDE inherit these variables, create a dedicated script in /etc/profile.d/.

  1. Create a new configuration script:

    sudo nano /etc/profile.d/proxy.sh

  2. Add the export commands:

    export http_proxy="http://proxy.example.com:8080/"
export https_proxy="http://proxy.example.com:8080/"
export ftp_proxy="http://proxy.example.com:8080/"
export no_proxy="localhost,127.0.0.1,localaddress,.localdomain.com"
export HTTP_PROXY="http://proxy.example.com:8080/"
export HTTPS_PROXY="http://proxy.example.com:8080/"
export FTP_PROXY="http://proxy.example.com:8080/"
export NO_PROXY="localhost,127.0.0.1,localaddress,.localdomain.com"

  3. Save, exit, and grant execution permissions to the script:

    sudo chmod +x /etc/profile.d/proxy.sh

Step 3: Configure Package Managers (APT)

Most Debian- and Ubuntu-based systems running LXDE require explicit proxy rules for the package manager, as sudo commands do not automatically inherit user-level proxy environment variables.

  1. Create an APT proxy configuration file:

    sudo nano /etc/apt/apt.conf.d/95proxies

  2. Insert your proxy details:

    Acquire::http::Proxy "http://proxy.example.com:8080/";
Acquire::https::Proxy "http://proxy.example.com:8080/";
Acquire::ftp::Proxy "http://proxy.example.com:8080/";

  3. Save and close the file.

Step 4: Apply Changes and Verify

  1. Reboot your system to apply all changes across the display manager and LXDE sessions:

    sudo reboot

  2. Once logged back into LXDE, open LXTerminal and check if the variables are active:

    echo $http_proxy
echo $https_proxy

  3. Test network connectivity through the proxy:

    curl -I https://www.google.com

Web browsers like Chromium or Firefox ESR running inside LXDE will default to system proxy settings. If a browser does not automatically pick up the system configuration, navigate to its internal connection settings and set the proxy option to "Use system proxy settings."
