How to Configure Core Dumps for LXDE Module Crashes

When LXDE desktop components such as lxpanel or pcmanfm crash unexpectedly, core dumps provide essential forensic data to identify memory corruptions, segmentation faults, and stack traces. This guide explains how to configure system-wide core dump generation, adjust user session resource limits for LXDE, and inspect the resulting dumps using debugging utilities like GDB.

1. Enable Core Dump Size Limits

By default, Linux systems set the core file size limit to zero, preventing dump generation. You must lift this restriction.

To apply this persistently across user sessions, edit /etc/security/limits.conf:

*               soft    core            unlimited
*               hard    core            unlimited

Because LXDE sessions are launched via display managers (like LightDM) or direct X initiation, ensure the limit is exported directly inside the user session. Add the following line to ~/.xprofile or /etc/xprofile:

ulimit -c unlimited

2. Configure Core Dump Handling

Choose one of two methods to capture and store the dump files: modern systemd-coredump or the traditional kernel handler.

Option A: Using systemd-coredump (Recommended)

If your distribution uses systemd, install the coredump utility:

sudo apt install systemd-coredump  # Debian/Ubuntu
sudo pacman -S systemd-coredump    # Arch Linux

Configure storage settings in /etc/systemd/coredump.conf:

[Coredump]
Storage=external
Compress=yes
ProcessSizeMax=2G

Restart the systemd socket to apply changes:

sudo systemctl daemon-reload

Option B: Using Traditional Kernel Patterns

If running without systemd, define the storage directory and naming convention directly in the kernel via sysctl.

Create /etc/sysctl.d/60-coredump.conf:

kernel.core_pattern = /var/crash/core-%e-pid-%p-sig-%s-time-%t
fs.suid_dumpable = 2

Create the storage directory and set appropriate permissions:

sudo mkdir -p /var/crash
sudo chmod 1777 /var/crash
sudo sysctl --system

3. Install LXDE Debug Symbols

Core dumps are of limited use without debugging symbols. Install the debug packages corresponding to the LXDE module you are diagnosing:

  • Debian / Ubuntu:

    sudo apt install lxpanel-dbgsym pcmanfm-dbgsym libfm-dbgsym

    (Note: You may need to enable debug repositories in /etc/apt/sources.list.d/).

  • Fedora:

    sudo dnf debuginfo-install lxpanel pcmanfm libfm

  • Arch Linux: Enable debuginfod support or compile the specific package from the AUR/ABS with options=(debug !strip).

4. Trigger and Inspect the Core Dump

To verify that your configuration works, kill a running LXDE module with an abort signal:

killall -SIGABRT lxpanel

Inspecting with systemd

List recorded crashes:

coredumpctl list lxpanel

Open the most recent crash directly in GDB:

coredumpctl gdb lxpanel

Inspecting with GDB Directly

If using standard kernel patterns, open the core file located in your designated directory (/var/crash):

gdb /usr/bin/lxpanel /var/crash/core-lxpanel-pid-*-time-*

Once inside the GDB shell, generate a full stack trace to pinpoint the cause of the failure:

(gdb) bt full
