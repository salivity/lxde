How LightDM Detects and Launches an LXDE Session

Display managers like LightDM identify and execute desktop environments by scanning standardized directory locations for session configuration files, parsing their execution commands, and launching the appropriate initialization scripts upon successful user authentication. This article explains the exact step-by-step mechanism LightDM uses to discover the Lightweight X11 Desktop Environment (LXDE), present it in the greeter menu, and hand off control to LXDE's session manager.

1. Session Discovery via .desktop Files

LightDM adheres to the freedesktop.org Desktop Entry Specification to detect available desktop environments on a Linux system. When the LightDM daemon starts, it searches designated directories for valid session definitions:

  • /usr/share/xsessions/ (system-wide sessions)
  • /usr/local/share/xsessions/ (locally compiled sessions)
  • /etc/X11/sessions/ (legacy support on certain distributions)

For LXDE, the system places a file named lxde.desktop in /usr/share/xsessions/. A standard lxde.desktop file contains key-value pairs structured like this:

[Desktop Entry]
Type=Application
Name=LXDE
Comment=LXDE - Lightweight X11 Desktop Environment
Exec=startlxde
Terminal=false
Icon=lxde
Type=Application
DesktopNames=LXDE

2. Presenting LXDE in the Greeter

During boot, LightDM launches a "greeter" (such as lightdm-gtk-greeter or slick-greeter), which provides the graphical login interface:

  1. Parsing: LightDM reads the Name and Icon keys from every .desktop file found in the xsessions directories.
  2. Populating: It populates the session selection drop-down menu with these entries, displaying "LXDE" as an option.
  3. Remembering Preferences: If a user previously selected LXDE, LightDM records this preference (typically in /var/lib/lightdm/.history or the user's configuration cache) to load LXDE by default on the next login attempt.

3. User Authentication

When the user enters their credentials:

  1. LightDM passes the username and password to the Linux Pluggable Authentication Modules (PAM) stack (located at /etc/pam.d/lightdm).
  2. PAM verifies the credentials, checks account status, and establishes the user session limits.
  3. Once authenticated, LightDM drops root privileges and prepares to launch the graphical environment under the user's specific User ID (UID) and Group ID (GID).

4. Executing the Session Wrapper

LightDM does not run the desktop executable directly. Instead, it sources a system-wide wrapper script, commonly /etc/X11/Xsession or /etc/lightdm/Xsession, and passes the command specified in the .desktop file's Exec line as an argument.

In the case of LXDE, the command passed is startlxde.

The wrapper script performs essential house-cleaning tasks:

  • Loads user environment variables from ~/.profile, ~/.bash_profile, or ~/.xprofile.
  • Starts the D-Bus session bus if it is not already running.
  • Loads X11 resources via xrdb and keymaps via xmodmap.
  • Handles session management via ssh-agent or gpg-agent if configured.

5. Initialization via startlxde

At the end of the wrapper chain, the system executes startlxde, which is a shell script located in /usr/bin/startlxde. This script completes the startup process:

  1. Environment Setup: It sets critical environment variables, including XDG_CURRENT_DESKTOP=LXDE and XDG_MENU_PREFIX=lxde-, ensuring applications identify the running environment correctly.
  2. Session Manager Execution: The script terminates by executing exec lxsession -s LXDE -e LXDE.
  3. Component Spawning: The lxsession binary takes over and automatically launches the individual components that comprise the LXDE desktop based on the configuration in /etc/xdg/lxsession/LXDE/autostart:
    • The Openbox window manager (openbox)
    • The desktop panel (lxpanel)
    • The desktop background and file manager (pcmanfm --desktop)
    • Polkit authentication agents and clipboard tools

LightDM monitors this root process. When the user logs out, lxsession terminates, signaling LightDM to clean up the user's processes and display the greeter screen once again.
