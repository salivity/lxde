LXDE Desktop Session Termination Script Explained

When logging out of the Lightweight X11 Desktop Environment (LXDE), users often expect a predefined logout script to execute cleanup tasks or save application states. This article explains the exact sequence of events during an LXDE session shutdown, reveals whether LXDE includes a native pre-termination script, identifies the system-level scripts triggered by display managers upon logout, and demonstrates how to execute custom scripts immediately prior to session termination.

Does LXDE Have a Native Pre-Termination Script?

By default, LXDE does not execute a built-in user shell script (such as a hypothetical logout.sh or shutdown) immediately prior to session termination.

While LXDE provides an autostart file located at ~/.config/lxsession/LXDE/autostart or /etc/xdg/lxsession/LXDE/autostart for initialization, it lacks an equivalent native configuration file for shutdown events.

When a user initiates a logout, the following sequence occurs within LXDE:

  1. lxsession-logout is called: This binary presents the shutdown, reboot, or logout GUI dialog.
  2. Signal transmission: Once confirmed, lxsession-logout sends a D-Bus message or a termination signal to lxsession.
  3. Process termination: lxsession terminates all child processes associated with the desktop session (such as openbox and lxpanel) and shuts itself down.

Because this termination sequence is handled internally by the compiled lxsession binary, no shell script is invoked natively at the desktop environment level.

Display Manager Scripts That Run on Termination

While LXDE itself does not trigger a shutdown script, the underlying Display Manager (DM) controlling the X11 session executes specific cleanup scripts as the session closes.

Depending on the display manager installed on the system, one of the following scripts executes immediately prior to or upon session termination:

  • LightDM: Runs the script defined by the session-cleanup-script directive inside /etc/lightdm/lightdm.conf. This script runs as root after the desktop session ends.
  • GDM (GNOME Display Manager): Executes /etc/gdm/PostSession/Default (or /etc/gdm3/PostSession/Default on Debian/Ubuntu systems) immediately after the session exits.
  • SDDM: Executes /usr/share/sddm/scripts/Xstop or /etc/sddm/Xstop.
  • XDM / Legacy X11: Executes /etc/X11/xdm/Xreset or /etc/X11/Xreset.

Note: Display manager post-session scripts run with root privileges rather than the logged-in user's privileges.

How to Run a Custom Script Before LXDE Terminates

If an automated script must run as the standard user immediately before LXDE shuts down, use one of the two standard implementations below.

Method 1: Wrapping lxsession-logout

Because LXDE invokes /usr/bin/lxsession-logout when logging out, replace or wrap this binary with a custom script:

  1. Move the original binary:

    sudo mv /usr/bin/lxsession-logout /usr/bin/lxsession-logout.orig

  2. Create a new /usr/bin/lxsession-logout wrapper script:

    #!/bin/bash
# Run your pre-logout commands here
if [ -f "$HOME/.config/lxsession/LXDE/pre-logout.sh" ]; then
    bash "$HOME/.config/lxsession/LXDE/pre-logout.sh"
fi

# Pass control back to the original logout binary
exec /usr/bin/lxsession-logout.orig "$@"

  3. Make the wrapper executable:

    sudo chmod +x /usr/bin/lxsession-logout

Method 2: Trapping Signals in ~/.xsession or ~/.xinitrc

If launching LXDE via startx or an .xsession file, intercept the exit signal using a shell trap:

#!/bin/bash

cleanup() {
    # Commands to run prior to termination
    /path/to/cleanup-script.sh
}

trap cleanup EXIT

exec lxsession -s LXDE -e LXDE

When lxsession exits, the cleanup function triggers immediately before the shell process terminates the X server.
