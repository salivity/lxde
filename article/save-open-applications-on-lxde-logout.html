Save Open Applications on LXDE Logout

The Lightweight X11 Desktop Environment (LXDE) manages login and logout procedures through its native session manager, LXSession. However, because LXDE is designed for minimal resource consumption, LXSession lacks native support for saving application states across sessions. To automatically restore open windows and running applications upon logging out, users must integrate an XSMP-compliant session manager like xfce4-session into LXDE, or use operating system hibernation.

The Native Component: LXSession

The default tool responsible for managing the session lifecycle in LXDE is LXSession (often interfaced via lxsession-logout).

  • Functionality: LXSession starts desktop components (like Openbox and PCManFM) and executes startup programs configured in the autostart file.
  • Limitations: It does not implement the X Session Management Protocol (XSMP) for running clients. When you log out, LXSession terminates all active processes without recording their layout, open files, or window coordinates.

The Solution: Using xfce4-session

The standard tool used to achieve true application state saving in an LXDE environment is xfce4-session, borrowed from the Xfce desktop environment.

xfce4-session includes a built-in session-saving engine that queries running applications via XSMP before logout, writes their state to disk, and relaunches them upon the next login.

To use xfce4-session to save open applications in LXDE:

  1. Install the package: Install xfce4-session through your distribution's package manager.
  2. Replace the session manager: Edit the LXDE session configuration (typically located at ~/.config/lxsession/LXDE/desktop.conf or /etc/xdg/lxsession/LXDE/desktop.conf) and replace the default session manager entry with xfce4-session.
  3. Enable session saving: Open the Xfce session settings within your environment and check the option labeled "Automatically save session on logout."

Alternative: System Hibernation

If you do not want to alter LXDE's underlying components, the system-level tool systemctl hibernate serves as an alternative. Rather than ending the user session, hibernation dumps the current contents of RAM to swap space, powering off the machine while keeping all open applications, unsaved buffers, and window states fully intact for the next boot.
