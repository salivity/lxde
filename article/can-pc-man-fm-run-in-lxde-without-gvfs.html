Can PCManFM Run in LXDE Without GVFS?

PCManFM can function as a file and desktop manager in LXDE without the full GVFS (GNOME Virtual File System) backend installed, making it suitable for extremely resource-constrained systems. Because PCManFM interfaces primarily with libfm and GLib's native GIO layer, core local file management remains functional. However, bypassing the complete GVFS stack removes several integrated desktop conveniences, requiring manual configuration or alternative tools for tasks like automounting and network browsing.

How PCManFM Interacts with GVFS

PCManFM does not hard-depend on the entire GVFS suite to run. Instead, it relies on libfm, which interacts with the underlying operating system using GLib’s GIO interface.

GVFS acts as an extension module for GIO, providing virtual abstraction layers for specialized file protocols and desktop services. When GVFS is absent, GIO falls back to standard POSIX calls for local filesystem operations. As a result, the PCManFM interface will launch, display your desktop, and allow you to interact with the local filesystem normally.

Functional Core Capabilities Without GVFS

Without the full GVFS backend, you retain all essential local file operations:

  • Local Navigation: Browsing local directories, root partitions, and mounted drives.
  • Basic File Operations: Creating, copying, moving, renaming, and directly deleting files and directories.
  • Desktop Management: Running pcmanfm --desktop to manage desktop icons, wallpaper rendering, and the LXDE desktop window.
  • Application Launching: Opening files with associated default applications based on MIME types and .desktop files.
  • File Properties: Viewing permissions, file sizes, and modifying standard POSIX read/write/execute rights.

Features That Break Without GVFS

Eliminating the GVFS backend removes specific high-level virtual abstraction layers:

  • The Trash Can: The trash:// protocol is provided by GVFS. Without it, PCManFM cannot move items to a desktop trash bin; files must be deleted permanently directly from the drive.
  • Removable Media Automounting: PCManFM relies on GVFS and UDisks to detect and automount USB flash drives, external hard disks, and optical media via the sidebar. Without GVFS, external drives will not show up automatically when plugged in.
  • Remote Network Shares: Network file protocols such as SFTP (sftp://), SMB/Samba (smb://), FTP (ftp://), and WebDAV (dav://) will fail to open in the PCManFM address bar.
  • Mobile Devices: Accessing smartphones via MTP (mtp://) or PTP will not work through the graphical file manager interface.

Workarounds for a Minimal Setup

If your goal is to avoid the heavy resource footprint of the complete GVFS suite while keeping essential functionality:

  1. Manual or Lightweight Mounting: Use terminal utilities such as mount, lightweight mounting daemons like udevil, or user-space mounting tools like pmount to access USB storage.
  2. Network File Systems: Mount network shares directly at the kernel level via /etc/fstab, sshfs, or cifs-utils into standard local directories, which PCManFM can then navigate like normal local folders.
  3. Selective Installation: Most Linux distributions separate the core gvfs package from its extensive protocol backends (gvfs-backends, gvfs-smb, gvfs-fuse). Installing only the base gvfs package provides Trash support and basic drive mounting without pulling in the dependencies required for Samba, WebDAV, or remote browsing.
