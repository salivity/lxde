Auto-Mount USB Drives by Label in LXDE

This guide explains how to automatically mount USB drives with specific filesystem labels to dedicated directories in an LXDE desktop environment. While LXDE's default file manager, PCManFM, automatically mounts generic removable media under generic user paths, targeting specific labels for custom mount behavior requires integrating system-level tools. By using either /etc/fstab with systemd automount options or custom udev rules, you can ensure drives with specified volume labels are automatically mounted to designated locations upon connection.

Step 1: Identify the Filesystem Label

Before configuring auto-mounting, plug in the USB drive and determine its filesystem label and type using the terminal:

lsblk -f

Locate your USB device in the output and note the value in the LABEL column (for example, BACKUP_DRIVE) and the FSTYPE (such as ext4, vfat, or ntfs).

If the drive does not yet have a label, you can assign one using the appropriate utility:

  • ext4: sudo e2label /dev/sdX1 MY_LABEL
  • FAT32: sudo fatlabel /dev/sdX1 MY_LABEL
  • NTFS: sudo ntfslabel /dev/sdX1 MY_LABEL

(Replace /dev/sdX1 with your actual partition identifier).

Step 2: Create a Target Mount Point

Create the directory where you want this specific drive to be mounted:

sudo mkdir -p /media/BACKUP_DRIVE

Set the proper ownership so your LXDE user can read and write to it without root permissions:

sudo chown -R $USER:$USER /media/BACKUP_DRIVE

Step 3: Configure Auto-Mounting

You can achieve label-specific mounting using either the /etc/fstab approach (recommended for simplicity) or a udev rule (for dynamic mounting without static mount points).

Method A: Using /etc/fstab (Recommended)

Modern Linux distributions running LXDE utilize systemd, which supports on-demand mounting via /etc/fstab.

  1. Open /etc/fstab in a text editor with root privileges:

    sudo nano /etc/fstab

  2. Add the following entry to the bottom of the file:

    LABEL=BACKUP_DRIVE  /media/BACKUP_DRIVE  auto  nofail,x-systemd.automount,x-systemd.device-timeout=5,user  0  0
    • LABEL=BACKUP_DRIVE: Targets only devices with this filesystem label.
    • auto: Automatically detects the filesystem type.
    • nofail: Prevents boot hangs if the drive is not plugged in during startup.
    • x-systemd.automount: Mounts the drive automatically as soon as the path is accessed or the device is plugged in.
    • user: Allows non-root users to mount and unmount the volume.

  3. Reload systemd to apply the changes:

    sudo systemctl daemon-reload
sudo systemctl restart remote-fs.target

Method B: Using a udev Rule

If you require the drive to mount instantly upon insertion without waiting for directory access, use a udev rule paired with systemd-mount.

  1. Create a new udev rule file:

    sudo nano /etc/udev/rules.d/99-usb-by-label.rules

  2. Add the following line:

    ACTION=="add", SUBSYSTEM=="block", ENV{ID_FS_LABEL}=="BACKUP_DRIVE", RUN{program}+="/usr/bin/systemd-mount --no-block --automount=yes --collect $devnode /media/BACKUP_DRIVE"

  3. Reload the udev rules:

    sudo udevadm control --reload-rules
sudo udevadm trigger

Step 4: Adjust PCManFM Settings to Avoid Mount Conflicts

By default, PCManFM attempts to auto-mount all removable devices via udisks2, which may result in conflicting duplicate mounts.

  1. Open PCManFM.
  2. Go to Edit > Preferences > Volume Management.
  3. If you want only your specifically configured drives to mount, uncheck Mount removable media when inserted.
  4. If you keep generic auto-mounting enabled, PCManFM will typically respect existing /etc/fstab entries and mount your labeled drive to the custom path rather than the default /media/<username>/ directory.
