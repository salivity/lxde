Why Is LXDE Still Maintained Alongside LXQt?

Despite the creation of LXQt as its modern, Qt-based successor, the lightweight X11 Desktop Environment (LXDE) remains actively maintained rather than abandoned. While LXQt represents the future direction envisioned by many of the original developers, LXDE continues to exist due to its ultra-low system requirements, feature-complete state, stability on legacy hardware, and continued demand from major distributions that rely on a dependable, GTK-based lightweight desktop.

The Origins of the Split

LXDE was originally built around the GTK 2 toolkit. When the GTK project moved toward GTK 3—introducing design changes, deprecations, and increased resource consumption—LXDE developers sought alternatives. This led to experiments with Qt, eventually merging with Razor-qt in 2013 to form LXQt. However, the creation of LXQt did not mark an abrupt end to LXDE. Instead of discarding the original codebase, the project bifurcated: LXQt focused on modern, forward-looking Qt-based development, while LXDE transitioned into a maintenance-focused model.

Ultra-Low Memory Footprint on Legacy Hardware

While LXQt is lightweight compared to GNOME or KDE Plasma, LXDE still consumes fewer resources, particularly initial RAM. The Qt framework libraries introduce a baseline memory overhead that can impact devices with 512 MB of RAM or less. For vintage computers, embedded boards, and lightweight virtual machines, LXDE offers one of the lowest possible operational footprints for a fully functional desktop environment.

The "Feature Complete" Philosophy

LXDE operates on the principle that software can eventually be "done." It is not trying to reinvent its user interface, add complex animations, or adopt modern design trends. Because its scope is intentionally limited, LXDE requires very little ongoing development. Maintenance largely consists of:

  • Fixing critical bugs and security vulnerabilities.
  • Ensuring compatibility with newer versions of dependencies (such as maintenance releases for GTK and X11).
  • Porting components where necessary to keep them compilable on modern Linux systems.

Because the day-to-day maintenance burden is low, a small group of volunteer maintainers can keep the desktop functional without diverting significant resources from other projects.

GTK Stack Preference and Modularity

Desktop environments often dictate the core libraries running in the background. Users and system administrators who predominantly run GTK-based applications often prefer LXDE over LXQt to avoid loading both GTK and Qt runtimes into memory. Furthermore, LXDE consists of modular, loosely coupled components—such as the PCManFM file manager, LXPanel, and the Openbox window manager. Several of these standalone utilities remain popular across other minimal window manager setups regardless of the full desktop environment.

Ongoing Distribution Support

Distributions like Debian and Arch Linux continue to package and maintain LXDE because a stable user base requests it. Long-term operating system ecosystems prioritize giving users predictable, functional choices that do not break established workflows. As long as base libraries remain compatible and maintainers are willing to submit patch releases, distributions will continue to ship LXDE as a reliable choice for lightweight computing.
