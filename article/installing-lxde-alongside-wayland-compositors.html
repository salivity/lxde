Installing LXDE Alongside Wayland Compositors

You can install LXDE alongside system services running standard Wayland compositors on the same Linux operating system. Although LXDE natively relies on the traditional X11 display server, Linux package management systems support having both X11-based and Wayland-based stacks installed concurrently. Depending on your configuration, these environments can be selected individually at login or run simultaneously across separate virtual terminals (TTYs) without library conflicts.

Compatibility Between LXDE and Wayland

LXDE (Lightweight X11 Desktop Environment) relies on Openbox and legacy X11 display architecture. It lacks native support for the Wayland protocol. Modern Wayland compositors, such as Weston, Sway, Cage, or Mutter, act as both the display server and the window manager.

Because standard distributions separate the shared libraries for X11 (libX11, xserver-xorg) and Wayland (libwayland-client, libwayland-server), installing LXDE does not overwrite or corrupt existing Wayland configurations or systemd service units.

Running Concurrent Sessions

You can run an LXDE user desktop and a Wayland-based system service at the same time using distinct Linux Virtual Consoles (TTYs):

  1. Virtual Terminal Separation: Direct Rendering Manager (DRM) and Kernel Mode Setting (KMS) allow different display servers to manage distinct virtual terminals. A Wayland kiosk service can run on tty1, while an Xorg instance hosting LXDE runs on tty7.
  2. Switching Between Interfaces: Users can switch between the active Wayland service and the LXDE session using standard terminal hotkeys (such as Ctrl + Alt + F1 through F7).
  3. Multi-Seat Configurations: If the system is equipped with multiple graphics adapters or multi-seat hardware, systemd can assign the Wayland service to Seat 1 and the LXDE instance to Seat 0, enabling simultaneous output to separate physical monitors.

Shared Dependencies and System Resources

When running both systems side-by-side, consider the following resource and configuration requirements:

  • GPU and DRM Contention: Only one display server can hold the DRM master status on a single graphic card's display output at a time. The inactive TTY drops DRM master privileges, allowing the active session to render to the screen.
  • Display Managers: Standard display managers (such as LightDM, GDM, or SDDM) can detect both LXDE (via .desktop files in /usr/share/xsessions/) and Wayland sessions (in /usr/share/wayland-sessions/), allowing interactive switching on boot.
  • Xwayland Distinction: Installing LXDE is distinct from running X11 applications inside Wayland via Xwayland. LXDE requires a running Xorg server; it cannot currently run as a full shell directly inside a Wayland compositor.
