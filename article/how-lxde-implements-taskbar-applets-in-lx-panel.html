How LXDE Implements Taskbar Applets in LXPanel

This article provides an architectural overview of how LXDE's desktop panel, LXPanel, implements and manages taskbar applets. It explores the dynamic plugin architecture powered by GLib's module system, the lifecycle of a panel plugin, and the specific mechanisms the taskbar applet uses to interact with the X Window System to manage and display active application windows.

The Modular Plugin Architecture

LXPanel is constructed around a modular, plugin-based architecture written in C and built on the GTK+ toolkit. Rather than hardcoding desktop components into the main panel binary, LXPanel treats interface elements—including application launchers, system trays, clocks, and taskbars—as dynamically loadable plugins.

At runtime, LXPanel discovers and loads these applets as shared object files (.so) using GLib's GModule abstraction layer. This allows developers to compile applets independently of the main panel executable while ensuring high memory efficiency and execution speed.

The Plugin API and Lifecycle

Every LXPanel applet implements a standardized C interface defined in LXPanel’s core headers (such as plugin.h). A plugin registers itself by defining a PluginClass structure that provides metadata and essential lifecycle function pointers:

  • constructor / new_instance: Called when the panel instantiates the applet. It allocates plugin-specific memory structures, instantiates GTK+ widgets (typically a GtkBox or GtkButton), sets up event listeners, and attaches the resulting widget tree to the panel's layout container.
  • destructor: Invoked when an applet is removed or the panel shuts down. It frees allocated memory, disconnects signal handlers, and releases X11 resources to prevent leaks.
  • config: Provides a callback to generate a GTK-based settings dialog when the user edits applet preferences.
  • panel_configuration_changed: Signals the applet when the panel changes size, orientation, or monitor placement so it can recalculate layout dimensions dynamically.

Implementation of the Taskbar Applet

The taskbar is implemented as a specialized plugin, typically found in plugins/taskbar.c. Unlike static applets, the taskbar dynamically synchronizes its UI with running graphical applications using the X Window System.

1. EWMH and NetWM Tracking

The taskbar tracks running applications by interacting with the X server using the Extended Window Manager Hints (EWMH) / NetWM specifications:

  • The applet listens for root window property notify events, specifically monitoring _NET_CLIENT_LIST and _NET_CLIENT_LIST_STACKING.
  • When a window opens, closes, or changes state, the X server fires an event that the applet intercepts to update its internal task list.
  • State tracking monitors properties like _NET_WM_STATE (to detect minimized, maximized, or hidden windows) and _NET_ACTIVE_WINDOW (to visually highlight the currently focused application).

2. Window Item Construction

For each tracked window, the taskbar creates an individual button widget:

  • Icon Retrieval: The applet queries the _NET_WM_ICON property or parses the window's WM_CLASS to fetch an appropriate icon from the current GTK icon theme.
  • Title Resolution: It reads the _NET_WM_NAME or standard WM_NAME property to display the window's title string, truncating text as required by panel space constraints.
  • Grouping and Layout: If window grouping is enabled, instances of the same application class are nested under a single button associated with a dropdown menu.

3. Event Handling and Window Control

User interaction with taskbar buttons translates directly into X11 client messages sent back to the window manager:

  • Clicking an inactive window button sends a _NET_ACTIVE_WINDOW request to raise and focus the application.
  • Clicking an active window button typically toggles minimization by sending a request via _NET_WM_STATE.
  • Right-clicking instantiates a standard GTK context menu populated with actions (Minimize, Maximize, Move to Workspace, Close) that dispatch standard NetWM actions to the window manager.

Configuration and Persistence

LXPanel serializes the state of all plugins in plain-text configuration files located in ~/.config/lxpanel/<profile>/panels/. Within this configuration, a Plugin block defines type = taskbar alongside key-value pairs representing user preferences, such as icon sizes, grouping behaviors, and maximum taskbar button widths. When LXPanel initializes, its config parser reads this file, resolves the taskbar type to the compiled plugin module, and calls its entry point with the parsed configuration parameters.
